Q3

    
decline or cancel? Depends who you ask

    
The spec gives the three answers distinct meanings: accept means the user submitted, decline means the user explicitly said no, cancel means they dismissed it without choosing. Same probe, five situations:

    

      
situationclaude 2.1.310codex 0.164.0spec says

      
headless, formcancel 4 msdecline 2 msnobody was asked: no answer is "right"

      
headless, urlcancel 4 msdecline <1 mssame

      
on screen, Esc, formcancelcancelcancel

      
on screen, Esc, urlcanceldeclinecancel

      
on screen, nobody touches itno answer in 60 sno answer in 60 snothing, until your timeout

    

    
So a decline from codex may mean "nobody was there" or "the user closed the dialog", and a cancel from Claude Code looks the same whether a person pressed Esc or no terminal existed. Neither answer proves a person saw anything.

  


  

    
Q4

    
What your server should do about it

    
    
      
  1. Only accept with the content you asked for is consent. Treat decline and cancel the same: do not proceed.
    2. 
      
  2. Always pass a timeout. Left alone on screen, Claude Code and Codex held the question for the full 60 s and never answered or cancelled. Your timeout is the only thing that ends it.
    3. 
      
  3. Do not read "advertises elicitation" as "a person is there". Headless runs advertise it too.
    4. 
      
  4. Log accepts. Claude Code hooks can answer elicitations on the user's behalf, in about 20 ms.
    5. 
    


// TypeScript SDK
const r = await server.server.elicitInput(params, { timeout: 120_000 });
if (r.action !== "accept" || !r.content?.confirm) {
  return { content: [{ type: "text", text: "Not confirmed. Nothing was changed." }] };
}

  


  

    
Q5

    
How the probe works

    
    
      
  • Probe server. A stdio MCP server with four tools. Each one sends a raw elicitation/create (form, url, one sent to a client that never advertised it, and with --wait one that is left untouched) and logs the client's capabilities, the answer and the round trip in milliseconds.
    • 
      
  • Stand-in model. A local endpoint that speaks the Anthropic Messages, OpenAI Responses, Chat Completions and Gemini formats just well enough to call those tools in order. Every client gets its own temporary home and config.
    • 
      
  • Screen check. With --tui the client runs in a private tmux server. askwire watches for the probe's nonce on screen, records when it appeared, then presses Esc, or nothing at all for the untouched question.
    •
